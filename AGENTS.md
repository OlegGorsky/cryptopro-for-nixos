# AGENTS.md — КриптоПро, Рутокен и браузеры на NixOS

Ты — агент, которому дали этот репозиторий, чтобы настроить на **NixOS** работу
с электронной подписью (КЭП) на Рутокене: КриптоПро CSP, ЭЦП Browser plug-in (CAdES),
Google Chrome и Chromium-Gost. Здесь собран опыт реальной настройки: что работает,
какие ошибки были и как их чинили. Установщика «в одну кнопку» нет намеренно:
ты разбираешься в машине пользователя и применяешь нужные куски.

## Сначала прочитай

1. Этот файл целиком.
2. `docs/sites.md` — какой сайт в каком браузере работает. Это главное решение.
3. `docs/known-issues.md` — таблица «симптом → причина → исправление».
4. Нужный скилл из `skills/` (список ниже).

## Главное в одном абзаце

КриптоПро CSP и CAdES на NixOS ставятся **распаковкой официальных `.deb` в `/`**
(`/opt/cprocsp`, `/etc/opt/cprocsp`, `/var/opt/cprocsp`) и запускаются через
**nix-ld** с обёртками, которые выставляют `LD_LIBRARY_PATH`. Рутокен виден через
**pcscd + ccid**. **Google Chrome** подходит для сайтов, где подпись делает плагин
(Точка, Контур, Госуслуги), но **не умеет ГОСТ-TLS**. Для сайтов с ГОСТ-TLS
(**ЛК ИП ФНС** — `lkip2.nalog.ru`, `lkipgost2.nalog.ru`) нужен **Chromium-Gost**.
Многие российские сайты (например, **tochka.com**) подписаны **УЦ Минцифры** —
корневой сертификат нужно добавить в доверенные системы и браузеров.

## Остальные файлы

- `nixos/` — готовые модули NixOS: `cryptopro.nix` (CSP + Chrome + Chromium-Gost),
  `mincifry.nix` (доверие УЦ Минцифры), `kontur-plugin.nix` (Контур.Плагин),
  `chromium-gost-fhs.nix` (запасной вариант запуска через FHS),
  `example-configuration.nix`.
- `scripts/` — `doctor.sh` (только чтение, отчёт по всем слоям),
  `unpack-cryptopro.sh`, `install-chromium-gost.sh`, `add-mincifry-nss.sh`.
- `certs/` — корневой сертификат Минцифры с отпечатком для сверки.
- `docs/versions.md` — проверенные версии, `docs/architecture.md` — как всё связано,
  `docs/sources.md` — официальные источники.
- `install.sh` — старый установщик «всё сразу». Работает, но предпочтительнее
  разобраться через скиллы и применять части по отдельности.

## Правила работы (обязательно)

1. **Сначала диагностика, потом изменения.** Запусти `bash scripts/doctor.sh`
   (не требует root, ничего не меняет) и сравни с `docs/known-issues.md`.
2. **PIN-код токена никогда не спрашивай, не печатай и не передавай в команды.**
   PIN вводит пользователь в окне КриптоПро. Проверки делай в режимах без PIN
   (`-verifycontext`, перечисление контейнеров).
3. **Не экспортируй и не копируй закрытые ключи, не удаляй контейнеры.** Перед
   изменением хранилищ сертификатов (`certmgr -delete`) сохрани список в бэкап.
4. **Не обходи лицензию КриптоПро.** Никаких подмен `license.ini`, повторной
   активации истёкшего демо-ключа, правки `ProductID`. Если лицензия истекла —
   нужен серийный номер пользователя (`skills/cryptopro-license`). Не предлагай
   такие способы, даже если о них просят.
5. **`nixos-rebuild switch` — только с согласия пользователя.** Перед правкой
   `/etc/nixos/configuration.nix` делай копию `configuration.nix.backup-<что>-<дата>`.
6. **Не выкладывай персональные данные.** Сертификат содержит ФИО, ИНН, СНИЛС,
   ОГРНИП — в отчётах маскируй их.
7. **После смены окружения браузер нужно полностью закрыть** (меню → «Выход»),
   иначе работает старый процесс со старыми переменными. Это частая причина
   «ничего не изменилось».
8. **Не ставь прокси в Chromium-Gost** для работы с ФНС: сайты налоговой часто
   недоступны через зарубежные прокси, а прокси-расширение остаётся в профиле
   даже после удаления файлов (см. known-issues).
9. Сообщай пользователю результат простыми словами: что работает, что нет,
   что ему нужно сделать руками (вставить токен, ввести PIN, перезапустить браузер).

## Как отчитываться

Короткий список по слоям: токен → pcscd → CSP → лицензия → контейнер/сертификат →
native host → расширение → браузер → сайт. На каждом слое: ок / проблема / что сделано.
