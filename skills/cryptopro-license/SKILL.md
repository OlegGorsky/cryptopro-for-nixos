# Лицензия КриптоПро CSP

## Проверить

```bash
cpconfig -license -view
```

- `License validity: ... Expires: N day(s)` — работает. Если это демо (серийник
  начинается с `5050N...`, срок 90 дней) — предупреди пользователя заранее.
- `Error code:3` и `License is expired or not yet valid` — лицензия истекла.
  Без неё не работают ГОСТ-TLS (ЛК ФНС в Chromium-Gost) и подпись.

Файл лицензии — `/etc/opt/cprocsp/license.ini` (системный, его читают все программы).

## Встроенная лицензия

Сначала проверь, нет ли её в самом сертификате:

```bash
certmgr -list -store uMy | grep -E 'Embedded License|Not valid after'
```

`Embedded License : CryptoPro CSP` (так бывает у сертификатов УЦ ФНС)
означает, что для операций **с этим ключом** CSP может работать без отдельной
лицензии. Если вход/подпись всё равно не работают при истёкшей общей лицензии —
нужен серийный номер.

## Ввести серийный номер

Серийный номер покупается у КриптоПро или партнёров.
Формат: `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`.

Номер вводит пользователь сам — так он не попадёт в историю агента:

```bash
sudo cpconfig -license -set XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
cpconfig -license -view
```

Или через старый установщик, который спросит номер в терминале:

```bash
sudo bash install.sh license
```

После ввода перезапусти браузеры и `systemctl --user restart cryptopro-certprop`.

## Запрещено

- Подменять или «откатывать» `license.ini`, править `ProductID`, переустанавливать
  CSP ради нового пробного периода, использовать `-use_expired` для истёкшего
  демо-ключа. Это нарушает лицензию КриптоПро. Не предлагай такие способы,
  даже если о них просят.
- Просить серийный номер в чате и печатать его в логах.

## Если лицензия «видна» в терминале, но не в браузере

Браузер, скорее всего, в песочнице (Flatpak, snap) или в FHS без доступа к
`/etc/opt/cprocsp`. Решение — нативный браузер или проброс `/etc/opt/cprocsp`
в FHS (`nixos/chromium-gost-fhs.nix`). Копировать `license.ini` в профиль не надо.
