# Какой сайт — в каком браузере

Проверено на NixOS (GNOME), КриптоПро CSP 5.0, Рутокен, КЭП от УЦ ФНС.

| Сайт | Браузер | Что нужно | Почему |
|---|---|---|---|
| ЛК ИП ФНС — `lkip2.nalog.ru`, вход по сертификату через `lkipgost2.nalog.ru` | **Chromium-Gost** | CSP + лицензия, Рутокен, ГОСТ-TLS, расширение CAdES | Вход по сертификату идёт по **ГОСТ-TLS**. Google Chrome ГОСТ-TLS не умеет. |
| ЛК ФЛ / ЛК ЮЛ ФНС (`lkfl2.nalog.ru`, `lkul.nalog.ru`) | Chromium-Gost | то же | Тот же механизм входа по сертификату |
| Точка Банк — `tochka.com`, `i.tochka.com` | **Google Chrome** | **Корень Минцифры** в доверенных; для подписи — расширение CAdES | Сертификат сайта выпущен `Russian Trusted Sub CA`. Без корня: `ERR_CERT_AUTHORITY_INVALID`, «https зачёркнут» |
| Контур (Экстерн, Диадок и др.) | Google Chrome | Контур.Плагин + его native host, CSP | Работают через свой плагин `kontur.plugin` |
| Госуслуги (вход по ЭП) | Google Chrome | Расширение и плагин Госуслуг (IFCPlugin) | В этом наборе не проверялось — см. официальную инструкцию Госуслуг |
| Сайты с сертификатами Минцифры (часть банков, госсайты) | Chrome / Chromium-Gost | Корень Минцифры | Обычные браузеры ему не доверяют |

## Что не работает и не надо пытаться

- **Яндекс.Браузер из Flatpak + ГОСТ-TLS → `net_error -113`.** Внутри песочницы
  не видна `/etc/opt/cprocsp` (лицензия, конфиг), а даже с пробросом лицензии
  ГОСТ-TLS Яндекса на Linux не работает. По матрице КриптоПро ГОСТ-TLS Яндекса
  поддержан только в Windows. Используй Chromium-Gost.
- **Google Chrome на ЛК ИП ФНС** — страница «Проверка защищённого соединения…»
  с советами для Windows. Это общий шаблон ФНС: у Chrome просто нет ГОСТ-шифров.
- **Chromium-Gost через прокси** — сайты ФНС отвечали таймаутом или `502` через
  зарубежный прокси, а Chromium-Gost не подставляет логин прокси из расширения.

## Быстрая проверка, что ГОСТ-TLS до ФНС вообще проходит

Без браузера, только CSP:

```bash
csptest -tlsc -server lkipgost2.nalog.ru -port 443 -hello -nocheck -nosave -verbose
```

`-hello` отправляет только ClientHello и ждёт ответа сервера — PIN и токен не
нужны. В выводе должны быть ГОСТ-наборы `(c1 00) (c1 01) (c1 02) (ff 85) (00 81)`,
`... bytes of handshake data received` и `[ErrorCode: 0x00000000]`. Это значит, что
сеть и CSP в порядке, и проблему надо искать в браузере. Без `-hello` команда на
ФНС зависает (сервер ждёт клиентский сертификат). Справка: `csptest -tlsc -help`.

Это не проверяет лицензию: при истёкшей лицензии ClientHello проходит, а вход в
браузере — нет. Лицензию смотри отдельно: `cpconfig -license -view`.
